# Padrão de Commits

Formato:

```
tipo: descrição curta
```

## Tipos

| Tipo | Uso |
|---|---|
| `feat:` | nova funcionalidade |
| `fix:` | correção |
| `refactor:` | reorganização sem mudança de comportamento |
| `style:` | ajuste visual |
| `docs:` | documentação |
| `chore:` | manutenção |
| `perf:` | melhoria de desempenho |

## Exemplos

```
feat: adiciona nova seção da agenda
fix: corrige ordem dos elementos no mobile
style: ajusta proporção do mockup da conta digital
docs: atualiza documentação do projeto
refactor: reorganiza componente sem alterar comportamento
chore: organiza arquivos administrativos do repositório
```

## Boas práticas

- usar verbo no presente (ex.: "adiciona", não "adicionado" ou "adicionando");
- manter a mensagem curta e objetiva;
- não usar mensagens genéricas como "ajustes" ou "correções";
- não misturar várias tarefas no mesmo commit;
- não incluir arquivos não relacionados à mudança descrita.
